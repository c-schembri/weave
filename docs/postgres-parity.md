# PostgreSQL parity scope

Target: PostgreSQL 18's libpq capability set. Status describes implementation,
not production qualification. Unimplemented authentication or wire messages
fail explicitly; there is no silent fallback or fabricated success.

The [function-by-function API audit](postgres-api-audit.md) inventories all 193
functions in the qualified libpq 18 headers, distinguishes concrete mappings
from intentional differences, and records gaps hidden by broad category labels.
It is not a claim that all 193 capabilities are complete or deployment-qualified.

The [libpq manual](https://www.postgresql.org/docs/18/libpq.html) defines the
reference checklist. Low-level C memory/polling APIs will be mapped to owning
C++ values and Tasks rather than duplicated literally. Where Weave deliberately
enforces stronger TLS policy, document the difference instead of advertising
insecure compatibility as a feature.
